## Global Constraints

- Работа локальная. Не менять VPS/DNS/credentials, V1/Stitch, опубликованные snapshots, сохранённые пользовательские presets или финансовый backend. Не выполнять реальные платежи. GitHub feature branch можно фиксировать/push; никаких merge в release/default без отдельного решения.
- Код/appearance/product state разделены. Черновики операций и demo journal только в памяти сессии, не в appearance/localStorage/URL. Account/asset/network обязательны; unknown не zero/free/available.
- Сохранить все семь оформлений, button-material targets, icon packs, настройки группы/отдельных/icon-only кнопок, палитру, typography, фон и один WebGL host. Продуктовые улучшения не должны переопределять выбранный пользователем материал.
- Не обводить каждый control прямоугольником. Структура — отступы, типографика, лёгкая поверхность там, где нужна. Компактность, читабельные цифры, 44px hit targets, focus-visible. Не превращать текст в мелкую неразборчивую подпись ради плотности.
- Анимации существующими CSS/Motion: короткие press/переходы, спокойное завершение, без прыжков, blur/count-up денежных чисел. Reduced motion и lifecycle cleanup сохраняются. Нет новых animation/runtime dependencies.
- Один явный demo-контекст и недвусмысленное «Подтвердить симуляцию» достаточны; не повторять предупреждение в каждом абзаце. Неплатёжные реквизиты должны оставаться явно неплатёжными.
- Быстрый цикл владельца заменяет повторные лестницы skill review: один focused RED/GREEN для изменяемого поведения, без full suites у исполнителей; ORACLE один общий typecheck/build после объединения; root один связный browser visual. После исправления повторять только затронутую проверку. Реальный риск потери данных/денег/секретов не обходить.
- Только браузерный UI, не native Computer Use. Не открывать видимые терминалы/окна; фоновые PowerShell процессы с WindowStyle Hidden.
- Новые/возобновлённые рабочие чаты Astra MAX; subagents GPT-6.1 SOL MAX. Разделённое владение файлами; exact-path `git commit --only`, никаких add-all/reset/clean/branch switch. Root пишет план/issues, ORACLE владеет общей интеграцией.
