# Novex Wallet — reference-first motion и отдельная лаборатория примерки

## Задача и границы

Репозиторий: `i4w7w4a/Wallet_4i7`.
Известная рабочая ветка: `feat/23-react-bits-dashboard`, Draft PR #26.
На момент подготовки задания HEAD PR: `b08cf23e5066b9c870bd89b0cc8048d1f57b82a8`.
Перед началом проверь актуальный remote HEAD, handoff, инструкции репозитория и незавершённые изменения. Не ориентируйся автоматически на `main`.

Это отдельная задача, дополняющая проектирование компактной студии дизайна. В этой задаче разрешена реализация изолированной лаборатории анимаций. Основной Dashboard, пользовательскую Theme Studio и финансовые действия не переделывать. Предыдущее решение «главная без графиков» сохраняется, но удаление графиков не смешивать с этим PR.

Работай в отдельной ветке и worktree. Никаких force-push, merge существующих PR, закрытия Issues или публикации preview наружу без отдельной команды владельца.

## 1. Главный принцип

Нужен не набор простейших самодельных эффектов и не максимальное количество анимаций.

Нужен процесс:

**найти подходящие реализации → изучить исходное поведение → собрать живые варианты → дать дизайнеру настроить → сохранить выбранный вариант → отдельно интегрировать после разрешения.**

Использовать готовый компонент не означает автоматически получить хороший дизайн. Сохрани именно качества движения: характер ускорения, инерцию, затухание, реакцию на повторное действие, непрерывность и возвращение в исходное состояние.

Не заменяй выбранную выразительную анимацию обычным `scale + opacity` только ради простоты. Но и не усложняй эффект ради названия библиотеки. Из технически подходящих решений сначала выбирай по визуальному соответствию задаче, затем оптимизируй, не теряя характер движения.

Собственная реализация разрешена, когда готовая не подходит. Тогда укажи изученные источники, объясни отличие задачи и сравни свой результат с референсами в лаборатории.

## 2. Источники: не ограничиваться React Bits

Сначала проверь текущие `components.json`, `THIRD_PARTY_NOTICES.md`, зависимости и локальные адаптеры. Уже используемые компоненты не импортируй повторно.

Основной круг поиска:

- Cult UI — https://www.cult-ui.com/docs
  Особенно для компактного редактора: Toolbar Expandable, Morph Surface, Floating Panel, Color Picker. Каждый компонент сначала проверить по актуальному исходнику.
- Motion Primitives — https://motion-primitives.com/docs
  Magnetic, Transition Panel, Morphing Dialog/Popover и родственные взаимодействия.
- React Bits — https://reactbits.dev/
  Фоны, pointer-effects, текст и выразительные декоративные взаимодействия. Сравнивать с уже адаптированным WebThreads, а не добавлять ещё одну копию.
- Magic UI — https://magicui.design/
  Навигационные и локальные акцентные взаимодействия.
- Aceternity UI — https://ui.aceternity.com/components
  Свет, поверхности и отдельные интерактивные элементы.
- Motion — https://motion.dev/examples
  Официальные примеры и движок для компонентного движения.
- Codrops — https://tympanus.net/codrops/hub/
  Дополнительные оригинальные реализации, когда основной круг не покрывает задачу.

Это не список обязательных зависимостей. Не устанавливай все библиотеки. Для одной задачи изучи 2–3 действительно подходящих кандидата, по возможности из разных источников. Не добавляй заведомо плохой вариант ради количества. Не гоняй весь список для изменения одного отступа.

Не утверждай, что компонент используется на известных production-сайтах, если конкретные примеры не проверены. Наличие демо не является доказательством production-готовности.

Для каждого прототипа сохраняй: источник, конкретный файл/компонент, проверенную версию или commit, лицензию, зависимости, собственные изменения и нерешённые ограничения. Не приписывай сторонней библиотеке код, который написал сам. Не считай все наборы лицензированными под обычной MIT. Для продукта-конструктора отдельно зафиксируй вопросы о распространении заимствованных компонентов; не делай неподтверждённых юридических выводов.

## 3. Сделать правила постоянными для агента

Не ограничивайся этим разовым промптом.

Аккуратно дополни действующие инструкции репозитория коротким правилом reference-first и запретом внедрения неутверждённого motion. Не перезаписывай существующий AGENTS.md целиком.

Создай локальный instruction-only skill:
`.agents/skills/novex-motion-design/SKILL.md`.

У skill должны быть `name`, точное `description`, условия применения и последовательность работы. Он нужен для существенных визуальных изменений, а не для любой правки кода.

Подробный каталог вынеси в reference-файл skill, чтобы не загружать агенту все библиотеки при каждом обращении. В skill зафиксируй отдельно роль технической проверки и роль человеческого художественного решения.

Проверь доступные инструменты конкретного окружения. Для поддерживаемых registries используй shadcn MCP либо чтение исходников/registry вручную. Motion AI Kit рассматривай как доступ к документации и дополнительным инструментам, а не как обязательную покупку.

Не считать MCP подключённым только из-за записи в конфигурации: проверить реальный read/search. Не устанавливать случайные skill-паки и не менять глобальные настройки или разрешения агента без отдельного согласования. Не требовать платный доступ для первого работающего результата.

Официальные документы для проверки настройки:
- https://ui.shadcn.com/docs/mcp
- https://www.cult-ui.com/docs/mcp-server
- https://motion.dev/docs/ai-kit
- https://motion.dev/docs/ai-kit-install
- https://developers.openai.com/codex/skills/
- https://developers.openai.com/codex/guides/agents-md/

## 4. Novex Motion Lab — живая примерка до внедрения

Сделай отдельный маршрут лаборатории, например `/design-lab`, внутри существующей инфраструктуры, если аудит не выявит препятствий. Не строй ещё один большой фреймворк.

Лаборатория открывается как обычная страница/вкладка. Она не является пунктом пользовательского меню кошелька. По умолчанию отключена в публичном production-окружении; один только скрытый navigation link не считается изоляцией. Не публикуй её автоматически.

В первой версии:
- переключение двух-трёх кандидатов;
- одна большая интерактивная сцена;
- компактная панель настройки активного кандидата;
- запуск/пауза, сброс, сохранение варианта и экспорт пресета;
- краткая карточка происхождения и ограничений.

Не показывать десятки демонстрационных карточек сразу. Монтировать только активный эффект. Переключение кандидата должно останавливать предыдущий renderer, обработчики и loops.

Два вида просмотра одного и того же компонента:
1. Изолированная сцена — оценка самого движения.
2. В контексте Novex — те же параметры, реальный размер объекта, фон и контраст с текстом.

Контекстный режим не должен подключать платежи, менять состояние реального Dashboard или писать настройки его темы. Для мобильной композиции сохранить ограничение 480 px. На desktop сама оболочка лаборатории может быть шире, но не растягивать preview кошелька.

При сравнении различать верную адаптацию исходного эффекта и намеренно изменённую версию. Где возможно, дать переключатель «Референс / Novex» или документированную проверку исходного поведения. Не встраивать чужой сайт как обязательный iframe и не зависеть от его доступности во время просмотра.

## 5. Настройка человеческим языком

На первом уровне не более 3–5 художественных контролов для выбранного эффекта.

Для реакции на курсор возможны:
- «Сила реакции»;
- «Радиус влияния»;
- «Мягкость возврата»;
- «Упругость»;
- «Максимальное смещение».

Не создавать их формально, если конкретный эффект не поддерживает соответствующее поведение. Каждому контролу нужен реальный, проверяемый смысл. Точные stiffness/damping и прочие технические параметры можно спрятать в «Точную настройку».

Стартовые значения должны быть уже осмысленно настроены агентом. Владелец уточняет вкус, а не исправляет заведомо плохое движение.

Нужны видимое значение и точный ввод, не только slider. Основные иконки — с понятными подписями. Панель не должна перекрывать объект. Compact не означает мелкие труднодоступные кнопки.

Предусмотреть стабильные области нажатия, клавиатуру, focus-visible, touch и системное reduced motion. Не делать финансовые кнопки «убегающими» от указателя ради демонстрации magnetic effect.

## 6. Первая вертикальная итерация — одна pointer-сцена

Не заполняй лабораторию всеми эффектами сразу.

Сначала проверь, есть ли в репозитории утверждённый логотип Novex и пригодный для задачи исходник. Не путай его с аватаром профиля.

Если утверждённый asset есть, подготовь 2–3 варианта реакции этого логотипа на курсор. Сравнивай разные характеры поведения, а не только разные цвета.

Различай:
- движение цельного знака вслед за курсором;
- отталкивание отдельных элементов с возвратом;
- деформацию или изменение света.

Это не взаимозаменяемые эффекты. Magnetic не выдавать за физическое отталкивание отдельных частей. Если для разлёта нужна подготовка геометрии, опиши её отдельно; не выдумывай новый логотип и не разрезай брендовый asset произвольным образом без решения владельца.

Если пригодного asset нет, не блокируй всю задачу и не создавай фальшивый логотип. Первую работающую примерку сделай для уже существующей фоновой сцены: текущее поведение как контроль и 1–2 подходящих найденных варианта. Явно обозначь, что это сравнение фона, а не готовая анимация логотипа.

Следующую, ещё не реализуемую сцену запиши в backlog: компактный инструмент студии, раскрывающий настройку, с сравнением подходящих Cult UI и Motion Primitives реализаций.

Изображения не генерировать и не изменять. Использовать существующие разрешённые assets.

## 7. Воспроизводимая настройка и человеческое утверждение

Пресет лаборатории должен содержать:
- schemaVersion, sceneId, effectId и версию реализации;
- assetId/hash, когда asset влияет на результат;
- полные эффективные параметры, а не только отличия от defaults;
- выбранные цвета, размер/масштаб сцены и seed, если есть randomness;
- сведения об условиях просмотра и fallback;
- статус и комментарий дизайнера.

Различать «Сохранить вариант» и «Выбрать для внедрения».
Первое сохраняет эксперимент, второе фиксирует решение владельца о конкретной версии. Ни одно из них не должно молча менять кошелёк.

Выбор версии подтверждается только явным действием владельца, не решением агента и не зелёным тестом. После изменения параметров или реализации это новый черновик; прежнее утверждение не переносится автоматически.

Дай экспорт/импорт проверяемого JSON-пресета. Сохраняй лабораторию в отдельном storage namespace, не в `wallet4i7.theme.v1` или `wallet4i7.visual.v1`.

Не предполагается, что агент автоматически видит localStorage браузера пользователя. Экспортированный файл или явное сообщение с сохранённым в репозитории presetId — способ передать выбранный вариант агенту. Не отображай «Отправлено агенту», если такой интеграции реально нет.

Интеграция в основной интерфейс — отдельная задача после команды владельца. В неё переносится тот же проверенный компонент и утверждённый пресет, а не похожая анимация, написанная заново. После переноса требуется ещё одна примерка уже в настоящем контексте.

## 8. Качество поведения и технические проверки

Проверить мышью: медленное движение, быстрый проход, резкую смену направления, остановку, выход из сцены и повторный вход.

Для варианта с возвратом: никаких скачков на границе, дрожания при неподвижной мыши, накопленного смещения или бесконечной раскачки. Должно восстанавливаться ожидаемое исходное состояние. Новое событие не должно каждый раз бездумно перезапускать движение с нуля.

Если есть физическая симуляция, обеспечить корректную зависимость от времени и ограничение delta после неактивности; не завязывать ощущение на частоту кадров.

Проверить touch/fine pointer, resize, Strict Mode, скрытую вкладку, reduced motion, saveData и отсутствие WebGL, если он используется. Реальные устройства не считать проверенными по одной эмуляции viewport.

Переиспользовать установленный Motion/OGL там, где это соответствует эффекту. Новые runtime-зависимости добавлять только с обоснованием и проверкой лицензии. Не тащить одновременно несколько движков без необходимости. Не сбрасывать существующие aliases и настройки через CLI.

Тяжёлые эффекты загружаются только при выборе. В одной активной сцене не создавать несколько фоновых WebGL-контекстов. Неактивные варианты не продолжают работать скрыто.

Не отчитываться «стабильные 60 FPS» без измерений и указания окружения. Технический тест не является оценкой красоты. Художественное утверждение остаётся за владельцем.

## 9. Результат и точка остановки

Нужны:
1. Работающий изолированный Motion Lab с одной первой сценой и 2–3 кандидатами либо явно объяснённым более узким набором.
2. Краткие постоянные правила для агента, focused skill и проверенный каталог источников.
3. Сохранение/экспорт/импорт пресета с указанными выше границами.
4. Реальные тесты и короткий отчёт: что запускалось, что не проверено и какие ограничения остались.

Финальный ответ начни с того, как открыть лабораторию: реально проверенный локальный маршрут/команда или уже существующий доступный preview. Не выдумывай публичный URL. Если браузерный просмотр в текущем окружении недоступен, честно обозначь ограничение, но не выдавай статичный скриншот за проверенную интерактивность.

Затем перечисли кандидатов и что именно сравнивать. Скриншоты и запись движения — дополнение, а не замена возможности поводить мышкой самостоятельно.

Основной экран и пользовательские настройки должны остаться неизменными. Проверить отсутствие случайных CSS-утечек и импортов лаборатории в маршрут кошелька.

После предоставления лаборатории остановиться. Не выбирать окончательный вариант за дизайнера и не интегрировать его до отдельной команды.
