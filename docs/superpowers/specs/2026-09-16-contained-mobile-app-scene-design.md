# Wallet_4i7: изолированная мобильная сцена

Дата: 16 сентября 2026 года

Статус: на письменной проверке

Связанная работа: Draft PR #26

## 1. Проблема

Wallet_4i7 разрабатывается как мобильное приложение, но в браузерном режиме текущая композиция смешивает две разные области:

- содержимое Dashboard ограничено шириной `480px`;
- `WalletVisualLayer` закреплён через `position: fixed; inset: 0` и занимает весь viewport браузера.

Из-за этого WebThreads, свечение, маска и шум двигаются далеко за пределами интерфейса. На широком экране приложение воспринимается как узкая колонка поверх фоновой веб-страницы. Это противоречит текущей цели: проектировать единое мобильное приложение, а не desktop-сайт с мобильным виджетом.

## 2. Решение

Dashboard становится единственной визуальной сценой приложения:

- на viewport до `480px` сцена занимает всю ширину;
- на более широком viewport сцена имеет ширину `480px` и центрируется;
- WebThreads, fallback-постер, маски, шум, навигация и overlays ограничиваются той же сценой;
- пространство вне сцены остаётся неподвижным и нейтральным;
- внешний фон не получает цвета пользовательской темы, WebGL, шума, свечения или pointer-реакции;
- декоративная рамка телефона, Telegram chrome и имитация устройства не добавляются.

Так браузер остаётся удобной средой разработки, но показывает именно мобильное приложение.

## 3. Рассмотренные подходы

### A. Ограниченный viewport-layer — выбран

`WalletVisualLayer` остаётся привязанным к видимой высоте экрана, но получает ту же центрированную ширину, что и мобильная сцена. Это сохраняет текущую композицию shader, корректные pointer-координаты и небольшой WebGL framebuffer.

Преимущества:

- эффект не выходит за приложение;
- shader не растягивается на desktop;
- визуал не меняется во время прокрутки;
- мобильный и Telegram-режимы остаются полноэкранными.

### B. Absolute-layer на всю высоту документа — отклонён

Canvas можно было бы вложить в Dashboard через `position: absolute`. Тогда его высота зависела бы от всей прокручиваемой страницы, а не от viewport. Это увеличило бы framebuffer, исказило бы координаты WebThreads и ухудшило производительность без пользовательской пользы.

### C. Полностью удалить WebThreads — отклонён

Это устранило бы внешний фон, но одновременно убрало бы утверждённый живой визуальный материал внутри приложения. Проблема заключается в границах эффекта, а не в самом эффекте.

## 4. Геометрия сцены

Единый контракт ширины:

```text
scene width = min(100vw, 480px)
scene x = центр viewport
scene min-height = 100dvh
```

`wallet-dashboard` становится контейнером этой ширины. `wallet-dashboard__foreground` занимает `100%` контейнера и больше не задаёт независимый `max-width`.

`wallet-visual-layer` остаётся фиксированным по вертикали, но по горизонтали совпадает со сценой:

```text
top: 0
bottom: 0
left: 50%
width: min(100%, 480px)
transform: translateX(-50%)
overflow: hidden
```

Canvas и его декоративные слои продолжают занимать `100%` родительского visual layer. На настоящем мобильном viewport внешней области не существует.

## 5. Внешняя область браузера

`html` и `body` используют постоянный нейтральный цвет, не связанный с Theme Studio. Внешняя область:

- не анимируется;
- не реагирует на pointer;
- не содержит градиентов и шума;
- не получает glass blur;
- не имитирует корпус телефона;
- не участвует в пользовательской теме.

Граница приложения определяется только изменением материала и содержимым. Дополнительная рамка, тень или скругление корневой сцены не добавляются.

## 6. Навигация и overlays

Все элементы, принадлежащие приложению, должны соблюдать тот же горизонтальный контракт:

- нижняя навигация остаётся fixed, но центрируется внутри ширины сцены;
- `BottomSheet` и его backdrop покрывают только мобильную сцену;
- Theme Studio overlay и backdrop покрывают только мобильную сцену;
- фокус, Escape, возврат фокуса и safe-area продолжают работать без изменений.

Затемнение overlay не должно менять внешнюю область браузера. Пользователь всегда видит, что взаимодействует с одним приложением.

## 7. WebThreads и pointer

Сохраняются:

- один WebGL canvas;
- один постоянный RAF только в активном состоянии;
- остановка при hidden/inactive, reduced motion и saveData;
- fallback при недоступном WebGL;
- вычисление pointer-координат относительно canvas.

Движение указателя вне горизонтальных границ приложения не должно изменять WebThreads. Событие можно продолжать слушать на `window`, но координаты принимаются только при попадании pointer внутрь `canvas.getBoundingClientRect()`. При выходе target active плавно возвращается к нулю.

## 8. Изменяемые области

Предполагаемые изменения ограничены следующими зонами:

- `packages/ui/src/dashboard/dashboard.css`;
- `packages/ui/src/appearance/wallet-visual-layer.css`;
- `packages/ui/src/react-bits/web-threads/web-threads-engine.ts` — только фильтрация pointer вне canvas;
- CSS `BottomSheet` и dashboard theme overlay;
- компонентные и E2E-проверки геометрии сцены.

Публичные контракты темы, финансовые данные, структура Dashboard и количество визуальных эффектов не меняются.

## 9. Проверки

### Компонентные

- visual layer остаётся единственным;
- lifecycle WebThreads и fallback не меняются;
- pointer внутри canvas обновляет uniforms;
- pointer вне canvas не активирует эффект;
- overlays сохраняют доступность и focus trap.

### E2E

- на `390×844` и `430×932` приложение занимает всю ширину viewport;
- на desktop viewport `1024×900` Dashboard, visual layer, canvas и overlays имеют ширину `480px` и одинаковую центральную ось;
- точки слева и справа от сцены принадлежат статичному `body`, а не canvas;
- внешняя область сохраняет постоянный цвет при смене четырёх палитр;
- BottomSheet и Theme Studio не затемняют пространство вне приложения;
- horizontal overflow отсутствует;
- performance gate по RAF, render и canvas остаётся зелёным.

### Визуальные

- добавить desktop browser-preview screenshot с широкими статичными полями;
- существующие мобильные baselines не должны заметно измениться;
- движение WebThreads остаётся только внутри мобильной сцены.

## 10. Критерии готовности

Изменение готово, когда:

1. за пределами приложения нет движущихся или тематических слоёв;
2. на мобильном устройстве приложение по-прежнему занимает весь экран;
3. на desktop приложение центрировано и ограничено `480px` без декоративного device frame;
4. WebThreads видим и интерактивен только внутри приложения;
5. навигация, BottomSheet и Theme Studio используют те же границы;
6. reduced motion, reduced transparency, saveData и WebGL fallback сохранены;
7. unit, component, E2E, visual и performance проверки проходят.
