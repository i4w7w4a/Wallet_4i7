# CONTROL-FEEDBACK-01 — локальная примерка отклика кнопки

Статус: владелец утвердил `material` с `pressDepth: 2.7`, `magneticTravel: 5`, `settleMs: 270` как встроенный отклик четырёх быстрых действий MONO. Лаборатория остаётся локальным инструментом; решение о релизе координируется в [Issue #29, этап 4](https://github.com/i4w7w4a/Wallet_4i7/issues/29#issuecomment-5792610162). База: `codex/mono-release@6afcc5834624c1e9533a32ef29871b4603077813`.

## Что сравнивать

Один семантический button `168×48` с одинаковой надписью и одним тестовым callback. Baseline — нейтральный отклик. Material press меняет глубину поверхности и внутренний ход на нажатие; bounded magnetic сдвигает только текстовый слой вслед за fine pointer и мягко возвращает его. Изолированный и контекстный вид монтируют один `ControlFeedbackButton` с тем же config; контекст содержит только фикстуру без финансовых действий. Третья изученная механика, perimeter shimmer, отложена. Первичные исходники, лицензии и отличия описаны в [source-catalog.md](../source-catalog.md#12-control-feedback-01--проверка-одной-компактной-кнопки-2026-09-23).

## Проба

Dev-only адрес: `http://127.0.0.1:3118/design-lab` при `pnpm --dir apps/miniapp exec next dev -p 3118 -H 127.0.0.1`. В production route бросает `notFound()`. Страница отсутствует в пользовательской навигации.

Настройки: глубина press `0–3 px`, ход магнитного слоя `0–8 px`, мягкость возврата `100–320 ms`. Нерелевантный control блокируется. `Сравнить с базой` временно показывает baseline без записи. `Сохранить пробу` пишет только `novex.motion-lab.control-feedback-01.v1` в localStorage текущего origin; reload восстанавливает валидный snapshot. Export содержит полную versioned config, выбранный эффект, ширину и вид. Import ограничен 8192 символами, проверяет точные поля/версии/диапазоны, показывает кандидата и только затем применяет к черновику. Данные кошелька и product presets не участвуют.

## Вопросы визуального просмотра

1. При обычном быстром нажатии рельеф читается как материал или как лишняя тень?
2. Магнитный текст помогает почувствовать отклик или мешает попасть в кнопку?
3. Что лучше в размере `320 / 390 / 430 / 480`: baseline, material или magnetic?
4. Вернуться к одному из вариантов для доработки или оставить baseline?

Технический implementation SHA первой лаборатории: `71843df90af99ea2c94620f1a53066ac7ed6a1b2`. Вопросы выше относились к первому визуальному просмотру; затем владелец выбрал Material для быстрых действий.

## Отзыв владельца · 2026-09-23

После живого просмотра владелец положительно оценил отдельную настройку одной кнопки и удобство сравнения вариантов. Решение: **сохранить Motion Lab как способ собирать и обсуждать качественные варианты отдельных объектов**. Это одобрение процесса и текущей локальной примерки. В отзыве не назван выбранный `effectId` или JSON-проба; перенос в продукт не утверждён.

После уточнения владелец выбрал для первой локальной примерки группу четырёх быстрых действий MONO: «Отправить / Получить / Обмен / Купить». Launcher «Открыть быстрые настройки» скрыт на широком экране, а переключатель «Скрыть/Показать панели» является служебным chrome; эффекты на них не переносятся. Плитки `mono-actions` пока остаются визуальными `div`. Интерактивная примерка обязана дать им честную семантику и доступный отклик, сохранив явное сообщение о том, что финансовые операции в демо недоступны. Реальные операции и их action mapping эта задача не добавляет.

Один Lab snapshot применяется к этой группе четырёх одинаковых визуальных controls, а не ко всем кнопкам продукта. Размеры, композиция и смысл плиток сохраняются; адаптер переносит только отклик. Постоянное сохранение в рабочем пресете требует новой versioned схемы и не входит в эту локальную примерку.

### Решение владельца · этап 4

После просмотра четырёх действий владелец утвердил этот Material snapshot как встроенный default MONO. Все четыре кнопки получают его при первом рендере и после перезагрузки. `magneticTravel: 5` сохраняется как часть полной конфигурации, но в Material не исполняется. Отдельная лаборатория и её `Save`/временный `Apply` остаются только в dev; публичный preview показывает утверждённый default без доступа к `/design-lab`. Это решение не меняет `MonoWorkingDocument` v1 и не включает серверную библиотеку пресетов.

## Связь с отдельным окном MONO · локальная примерка

Владелец запросил путь «из настроек кнопки открыть отдельную лабораторию → настроить → применить в локальной сцене». Для первой связи выбрана **временная локальная примерка**, а не запись в текущий `MonoWorkingDocument` v1: его строгая схема сейчас допускает только `palette/shapes/optics/background`. Подмешивание движения без новой versioned migration нарушило бы импорт и старые рабочие пресеты.

В `/mono` ссылка **«Открыть Motion Lab»** находится в секции «Форма» при выбранной группе «Быстрые действия». Она открывает отдельную dev-only вкладку `/design-lab` с `session`, semantic target `mono.quick-actions` и, если есть, ID активного рабочего пресета. Lab-side протокол находится в `control-feedback-handoff.ts`. Кнопка **«Применить к локальной примерке MONO»** видна только при валидном запуске. Она отправляет полный проверенный snapshot через same-origin `BroadcastChannel` с отдельным `requestId`; Lab сам не пишет active config. Успех появляется только после совпадающего ACK. Чужая цель, старый сеанс, сменившийся рабочий пресет и неверные параметры получают явный отказ; отсутствие host даёт timeout. Закрытие вкладки, изменение draft, «Отменить изменения», Reset и «Сохранить пробу» сами по себе MONO не меняют.

MONO проверяет target, session, active working preset и схему перед тем, как показать один эффект на всех четырёх плитках. Плитки стали настоящими keyboard/touch controls только для проверки отклика: активация сообщает «операция недоступна в демо» и не запускает перевод, покупку или навигацию. Material сдвигает внутренний слой на press; magnetic двигает только подпись на fine pointer; reduced motion оставляет их статичными. Временный Apply не попадает в `MonoWorkingDocument` v1, исчезает после reload и не переходит к другому рабочему пресету; после reload возвращается утверждённый Material. Глаз баланса прорабатывается отдельно в [Issue #30](https://github.com/i4w7w4a/Wallet_4i7/issues/30).

Для других эффектов пригоден тот же порядок работы и подтверждения, но каждому объекту нужны собственные typed config, adapter и проверка ресурса. Текущая сцена отвечает только за CONTROL-FEEDBACK-01; общий мешок параметров и автоматическое применение ко всем кнопкам не вводятся.
