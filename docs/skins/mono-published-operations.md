# MONO: постоянные публичные адреса

`/p/1` … `/p/7` читают отдельные полные снимки оформления MONO v4. Они не читают рабочую библиотеку браузера. Обновление происходит только через явную команду редактора и `PUT /api/mono-published/[slot]` с ожидаемой ревизией. Пароль не требуется. Посетитель видит кошелёк с демоданными без редактора.

## Перед запуском

- `MONO_PUBLISHED_DATA_DIR`: существующий абсолютный каталог на постоянном томе **вне** checkout и image. Сервису нужны права чтения и записи. Каталог и его `history/` включаются в полную резервную копию вместе с метаданными тома.
- `MONO_PUBLISH_ORIGIN`: точный origin сервера редактора. В production это публичный HTTPS origin, например `https://wallet.95.181.213.4.nip.io`; он же возвращается клиенту как адрес `/p/N`. Origin не выводится из `Host` или `X-Forwarded-*`. В локальной разработке допустим точный `http://localhost:<port>` или `http://127.0.0.1:<port>`.
- `MONO_PUBLISHED_REMOTE_ORIGIN`: только для локальной разработки; точный публичный HTTPS origin основного сервера. Локальные `GET/PUT /api/mono-published/[slot]` направляются только к нему, а `/p/N` перенаправляет туда. Локальное хранилище не используется как запасной вариант.
- `MONO_PUBLISHED_FIXTURE_MODE=1`: отдельный режим локальных тестовых данных без удалённого сервера. Не совмещать с `MONO_PUBLISHED_REMOTE_ORIGIN` и не включать в production.

Без корректной конфигурации API отвечает `503`, а редактор не предлагает публикацию. `GET /api/mono-published/config` возвращает клиенту публичный origin для ссылок. Запись требует точный `Origin` редактора и `Sec-Fetch-Site: same-origin`, если браузер прислал этот заголовок; CORS не открывать. Это ограничение браузерного пути, **не аутентификация**: произвольный HTTP-клиент может указать такой `Origin` сам. Доступ к записи следует считать открытым для любого, кто достигнет API. Обновление конкурирующих редакторов защищает `expectedRevision`, но оно не определяет владельца.

## Сохранение и восстановление

`slot-N.json` — текущая запись; `history/slot-N/` содержит полную копию каждой принятой ревизии. Запись идёт во временный файл на том же томе, синхронизируется, затем атомарно заменяет текущую. Глобальный `.mono-publish.lock` защищает сравнение `expectedRevision` и запись между процессами. Один из двух одновременных запросов с той же ревизией получает `409`.

При обрыве процесса до замены текущего файла в истории может остаться кандидат, который ещё не стал публичным; авторитетен `slot-N.json`. При обрыве после замены ответ клиенту мог не дойти: сначала перечитать текущую ревизию, затем решать о новом обновлении. Повреждённая текущая запись даёт `503` и не перезаписывается автоматически; восстановить её из полной резервной копии или проверенной записи истории после остановки writer.

Если процесс погиб с `.mono-publish.lock`, публичное чтение остаётся доступным, а запись даёт `503`. **Не снимать lock по возрасту автоматически.** Оператор останавливает все процессы, способные писать MONO, подтверждает отсутствие живого writer, сохраняет полную копию каталога, проверяет текущие записи и историю, затем вручную удаляет только lock и запускает сервис. Исторический `auth-attempts.json`, если он остался на томе от прежней версии, больше не используется.

Перед обновлением image и перед миграцией сохранять полный том отдельно от image. Откат image не должен очищать том, истории или опубликованные семь адресов. Старый редактор может не показывать новые действия, но файлы публикаций остаются на томе для возвращения новой версии.
