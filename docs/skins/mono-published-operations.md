# MONO: постоянные публичные адреса

`/p/1` … `/p/7` читают отдельные полные снимки оформления MONO v4. Они не читают рабочую библиотеку браузера. Обновление происходит только через явную команду редактора и `PUT /api/mono-published/[slot]` с ожидаемой ревизией. Посетитель не входит в редактор; на странице остаются демоданные кошелька.

## Перед запуском

- `MONO_PUBLISHED_DATA_DIR`: существующий абсолютный каталог на постоянном томе **вне** checkout и image. Сервису нужны права чтения и записи. Каталог и его `history/` включаются в полную резервную копию вместе с метаданными тома.
- `MONO_PUBLISH_ORIGIN`: точный публичный HTTPS origin, например `https://wallet.95.181.213.4.nip.io`. Он не выводится из `Host` или `X-Forwarded-*` заголовков запроса. Для локальной проверки допустим `http://localhost` / `http://127.0.0.1` только вне production.
- `MONO_PUBLISH_PASSWORD_SCRYPT`: серверный хеш единого пароля в формате `scrypt$16384$8$1$<salt-base64url>$<hash-base64url>`. Функция `hashMonoPublishPassword` в серверном модуле генерирует его из пароля, который оператор получает без вывода в историю команд. Пароль и хеш не входят в Git, клиент, URL или логи.
- `MONO_PUBLISH_SESSION_SECRET`: случайные 32 байта в base64url. Хранить только в существующем секретном конфиге хоста. Смена ключа завершает все прежние сессии.

Без полного набора настроек вход и запись отвечают `503`. Чтение опубликованной записи требует только доступного тома. Сессия ограничена двумя часами; cookie `HttpOnly`, `SameSite=Strict`, `Secure` на HTTPS и доступна только под `/api/mono-published`. Для записи дополнительно нужны точный `Origin` и отдельный CSRF-токен в заголовке. Не открывать CORS для этих маршрутов.

## Сохранение и восстановление

`slot-N.json` — текущая запись; `history/slot-N/` содержит полную копию каждой принятой ревизии. Запись идёт во временный файл на том же томе, синхронизируется, затем атомарно заменяет текущую. Глобальный `.mono-publish.lock` защищает сравнение `expectedRevision` и запись между процессами. Один из двух одновременных запросов с той же ревизией получает `409`.

При обрыве процесса до замены текущего файла в истории может остаться кандидат, который ещё не стал публичным; авторитетен `slot-N.json`. При обрыве после замены ответ клиенту мог не дойти: сначала перечитать текущую ревизию, затем решать о новом обновлении. Повреждённая текущая запись даёт `503` и не перезаписывается автоматически; восстановить её из полной резервной копии или проверенной записи истории после остановки writer.

Если процесс погиб с `.mono-publish.lock`, публичное чтение остаётся доступным, а запись даёт `503`. **Не снимать lock по возрасту автоматически.** Оператор останавливает все процессы, способные писать MONO, подтверждает отсутствие живого writer, сохраняет полную копию каталога, проверяет текущие записи и историю, затем вручную удаляет только lock и запускает сервис. `auth-attempts.json` содержит постоянный счётчик ошибочных входов; не сбрасывать его для обхода ограничения.

Перед обновлением image и перед миграцией сохранять полный том отдельно от image. Откат image не должен очищать том, истории или опубликованные семь адресов. Старый редактор может не показывать новые действия, но файлы публикаций остаются на томе для возвращения новой версии.
